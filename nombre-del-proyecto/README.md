# Propuesta de Práctica Temática Pequeña (Documentación)

## 1. Título
**Diseño de una práctica pequeña de programación de sistemas con enfoque documental**

---

## 2. Descripción General
En esta actividad vas a **proponer y documentar** una práctica temática pequeña que pueda implementarse en uno de estos lenguajes:

- ARM64 Assembly
- Bash
- Python
- C

> **Ojo:** el objetivo principal **no** es programar el proyecto completo, sino demostrar que sabes **planearlo, justificarlo y estructurarlo** de forma profesional para un repositorio académico en GitHub Classroom.

La propuesta debe enfocarse en:

- Definir un caso de uso realista y acotado.
- Diseñar la estructura del repositorio.
- Explicar cómo se probaría el proyecto.
- Escribir documentación clara para que otra persona pueda continuar el trabajo.

### Restricciones del proyecto
Para mantener la actividad viable con herramientas gratuitas y tiempos de clase:

- El alcance debe ser **pequeño** (microproyecto).
- No usar frameworks complejos.
- No usar APIs pagadas.
- No usar bases de datos.
- No usar nube ni contenedores.
- No agregar dependencias difíciles de instalar.

### Resultado esperado
Al terminar, debes entregar una propuesta sólida que sirva como “plano” de implementación para una práctica corta de arquitectura de computadoras o programación de sistemas.

---

## 3. Entregables del Estudiante
Debes completar y mejorar los siguientes archivos:

1. `docs/propuesta.md`  
   - Tema elegido.
   - Lenguaje seleccionado (ARM64 Assembly, Bash, Python o C).
   - Objetivo técnico.
   - Alcance y límites.

2. `docs/caso_de_uso.md`  
   - Problema que resuelve.
   - Usuario objetivo.
   - Entradas/salidas esperadas.
   - Escenario de ejecución.

3. `docs/estructura_repositorio.md`  
   - Justificación de carpetas y archivos.
   - Flujo básico de trabajo.
   - Convenciones de nombres.

4. `docs/plan_de_pruebas.md`  
   - Casos de prueba mínimos.
   - Criterios de aceptación.
   - Evidencia esperada.

5. `test_plan.md`  
   - Resumen ejecutivo de pruebas para revisión rápida del docente.

6. `src/main.txt`  
   - Placeholder de la idea principal del programa (qué hará el archivo principal al implementarse).

7. `scripts/run.sh`  
   - Script mínimo para mostrar cómo se ejecutaría la práctica.

---

## Criterios de evaluación sugeridos

- Claridad técnica de la propuesta.
- Coherencia entre problema, alcance y solución propuesta.
- Calidad de documentación y redacción.
- Viabilidad real del proyecto en tiempo corto.
- Estructura limpia y profesional del repositorio.

---

## Recomendaciones finales
- Redacta como si otra persona fuera a implementar tu práctica sin hablar contigo.
- Usa ejemplos concretos y evita ambigüedades.
- Mantén el proyecto simple, funcional y comprobable.
